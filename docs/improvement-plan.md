# 改良計画 ─ 感動と爽快感の底上げ（ウェブ版）

- 作成日: 2026-09-23
- 対象: `web/` のみ（ネイティブ版 Processing + SC + Tidal は現状維持）
- 描画基盤: p5 2D を継続（WebGL 移行はしない）
- 想定デバイス: PC とスマホ両方（小型スピーカーで聞こえる音作りが必須）
- 優先軸: 爽快感・ゲーム性・楽器/音楽・感動/物語の 4 軸すべて（ユーザー選択）
- 状態: Phase 9-1〜9-4 すべて実装済み（2026-09-24）。経緯・ハマりどころは docs/process-log.md の Phase 9-1〜9-4

## 1. 診断 ─ 「動くが感動がない」原因

| # | 症状 | 根拠 |
|---|---|---|
| 1 | 溜めが 3 秒で頭打ち。満充填後は何も起きない | `main.ts` updateCharging で level を 1 にクランプ |
| 2 | 解放に「間」がない（吸い込み・ヒットストップ・無音なし） | triggerRelease が即時に全演出を発火。flash は 1〜2 フレーム |
| 3 | 爆発粒子が画面端でワープし放射形が崩れる | `visuals.ts` update() が全状態で wrapEdges |
| 4 | 小型スピーカーで低音がほぼ聞こえない（推定・未試聴） | dropBoom 60→28Hz sine、ドローン 40〜80Hz |
| 5 | 爆発がビートと無関係で音楽の「ドロップ」にならない | Strudel 層は 100bpm で独立進行、release は非量子化 |
| 6 | 毎回同じ結果・何も残らない | decay 後に完全に idle へ戻る |
| 7 | 触る前の誘いがない／タップが「弾いてる」感じにならない | idle はホバー無反応、pop の音程はランダム（x は pan のみ） |
| 8 | ネオンが発光して見えない | point 描画のみ、グローなし |

## 2. フェーズ計画

各フェーズ単体で遊べる状態で終え、体験確認（PC + スマホ実機の試聴）を挟んでから次へ進む。

### Phase 9-1 爽快感コア（解放の瞬間）

| ID | 内容 | 規模 |
|---|---|---|
| A1 | 3 段の解放シーケンス: 吸い込み約 80ms（粒子収縮・ズームイン・全音ミュート）→ ヒットストップ → 爆発（ズームアウトのパンチ + スローモーション 0.3→1.0） | S〜M |
| A2 | 速度ストリーク描画（線の長さ ∝ 速度） | S |
| A3 | 爆発中は端ワープ停止 → 画面外へ飛散、端から緩やかに再流入 | S |
| A4 | 多層衝撃波（白の先行波 + マゼンタ本波 + 粒子を押す歪み） | S |
| A5 | 色温度: 溜めでシアン→白熱、爆発で全色相、残光で元へ | S |
| A6 | 軽量グロー（縮小バッファをぼかして加算） | M |
| C1 | 小型スピーカー対策: キックに 2〜4kHz クリック + 100〜200Hz 胴 + 倍音歪み | S |
| C2 | ビルドアップ: 溜め中にノイズライザー + 加速スネアロール + フィルター開放、解放直前に約 100ms の無音 | M |
| C3 | ドロップのビート同期: 解放を次の 16 分に量子化、Strudel 層をドロップ区間（キック + ベース、長さ ∝ level）へ切り替え | M |

技術メモ:
- スローモーションは物理積分に `timeScale` を掛ける（現状 60fps 固定前提のチューニングは維持）
- A1 の吸い込み・無音と C3 の量子化待ちは同じ「解放前の猶予」に統合する（待ちが二重にならないように）
- 要調査: Strudel スケジューラの現在サイクル位置の取得方法（C3 の量子化の基準時刻。実装前に Context7 で確認）
- 要検証: A2 の line 描画 4000 本の負荷（色バケット単位で `drawingContext` に一括 path する案）、A6 の `ctx.filter` の Safari 対応（非対応ならダウンスケール→アップスケールの多段で代替）

### Phase 9-2 ゲーム性と溜めのドラマ

| ID | 内容 | 規模 |
|---|---|---|
| B1 | 段階チャージ: 33/66/100% で閾値演出（リング出現・和音が 1 段上がる・粒子が渦へ） | M |
| B2 | オーバーチャージ: 満充填後の保持で不安定化（軋み・Shepard トーン・赤化）、限界で暴発 = 最大爆発 | M |
| B3 | クリティカル: 心拍の頂点で離すと特殊演出 + 特殊音 | S |
| D3 | スリングショット: 離す瞬間の弾き方向・速度で指向性爆発 | S |
| D5 | ホバーで粒子が避ける・波紋（idle の誘い） | S |
| E4 | スマホ: 振って解放（DeviceMotion、iOS は許可要求）+ ハプティクス（`navigator.vibrate` は Android のみ） | S |

### Phase 9-3 楽器・音楽

| ID | 内容 | 規模 |
|---|---|---|
| C4 | 解放ごとにコード進行が進む（Cm→A♭→E♭→B♭）。シャワー・pop・Strudel 層が共有の和声状態を参照 | S |
| C5 | タップを楽器化: x = 音階度数、y = 音色/オクターブ | S |
| D1 | 種と連鎖爆発: タップで光の種を置き、本爆発の衝撃波が触れると誘爆（Boomshine 型） | M |
| D2 | 種のループシーケンサー: 置いた種がビートに合わせて鳴り続け、爆発で一掃 → 静寂 → 再構築 | M |

D1 はゲーム性の案だが、種を D2 と共有するためこのフェーズで実装する。

### Phase 9-4 感動・物語（体験の弧）

| ID | 内容 | 規模 |
|---|---|---|
| E1 | 「モヤモヤを書いて爆破」: 入力語を粒子が形作り、溜めて吹き飛ばす。入力はブラウザ内のみ（送信・保存しない） | M |
| E2 | 蓄積と大団円: 爆発ごとに残滓（星座・星雲・色の染み）が積もり、N 回目で一斉に爆ぜて夜明け色へシーン転換 | M〜L |

## 4. 検証の型（各フェーズ共通）

- 実測ゲート: `pnpm build`（tsc + vite）
- 自動 E2E: chrome-devtools で PointerEvent 合成（ゲート→溜め→解放・pop 連打）、コンソールエラー 0、`__heartburstAudio.getAmp()` で音の実出力を数値確認
- 性能: 各状態の fps とフレーム間隔分布（省エネ rAF 制限と真の負荷を区別 ─ process-log Phase 6 の罠 7）
- 体感: PC スピーカー / ヘッドホン / スマホ実機で人間が試聴・操作（機械判定できないので省略しない）
- デプロイはフェーズごとにユーザー確認のうえ実施
